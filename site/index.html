Pack an Elixir or Erlang release into one executable. Two steps.

For Erlang/OTP 28 · macOS and Linux · arm64 and x86_64 · Apache-2.0

What packing looks like

Before you start

Works

  • Phoenix, Ecto, Francis, SQLite, plain OTP: seven examples, each with an end-to-end suite.
  • NIFs in C, C++ or Rust, rebuilt for wasm when you pack. That needs wasi-sdk 34, and Rust NIFs also need rustup target add wasm32-wasip1-threads.
  • Host programs you allow: ports, System.cmd/3 and :os.cmd/1, with exit statuses, os_pid and {:packet, N} as on a native release.
  • Programs shipped inside the release, in priv/, with no allow list: they are extracted on first use and run on the host.
  • Unix domain sockets ({:local, path}) at the app’s own paths, host services included when you mount them in.
  • Erlang distribution with --node my_app@10.0.0.5: packed nodes cluster with each other and with native ones, on one known port or through the host’s epmd. remote and rpc reach a running node.
  • Elixir and Erlang/OTP 28 on the machine that packs. Nothing on the machine that runs.

Does not work

  • A program in priv/ built for another OS or CPU than the target: it cannot start there, and packing warns about it.
  • Starting epmd: without one on the host, every node of a cluster listens on the same distribution port, one node per address.
  • An OTP major other than 28: the engine runs ERTS 16.
  • A NIF thread that calls enif_thread_exit: it ends without cleanup and joining it never returns. Return from the thread function instead.

Good to know

  • The app reports itself as Linux on every host: :os.type() returns {:unix, :linux}. System.pid/0 is the real host pid.
  • A program the app starts runs on the host and sees the host’s files. Its path and cd: are translated from the app’s; its arguments are not.
  • Each run gets a private /tmp, removed when the app exits. A run that wrote erl_crash.dump keeps it and prints where.
  • Precompressed static files (.gz, .br) are not packed; Plug.Static serves the uncompressed file.
  • .beam files lose their debug and docs chunks, so Code.fetch_docs/1 has nothing to show.
  • The app sees only its mounts: the release at /app, a private /tmp, /etc/hosts, /etc/resolv.conf, the host's CA bundle, /dev/null, a generated /proc, and anything you pass with --mount. --listen, --port-map, --deny-connect and --rewrite-connect decide which ports it binds and where it may connect.

When you need more

None of these is a step. Each stands on its own: take the ones your app needs.

Running it

Start it, call into it

The file takes the release script’s commands: start, eval, and any you add.

If the app migrates a database before it starts, put the order in ampoule.toml at the project root. Packing stores it in the file.

$ ./my_app-aarch64-darwin start
$ ./my_app-aarch64-darwin eval 'IO.puts(MyApp.version())'
$ PORT=8080 ./my_app-aarch64-darwin serve
serve = ["migrate", "start"]

[commands]
migrate = "MyApp.Release.migrate()"

[start.env]
PHX_SERVER = "true"

Stop it

SIGTERM or Ctrl-C: the release shuts down through init:stop() and exits 0, as it would natively. A second signal, or an app still running after --stop-timeout, exits at once.

$ kill -TERM $PID
$ ./my_app-aarch64-darwin --stop-timeout 10 start

Cap its memory, restart it if it runs out

At 80% of the cap, OTP’s system_memory_high_watermark alarm goes up, so the app can shed load. If the VM still runs out, it starts again with its listening sockets held open. After five failures in five minutes it exits, for systemd or Kubernetes to take over.

$ ./my_app-aarch64-darwin --memory-max 512M \
    --restart on-failure start

Shipping it

In a container, alone

The file is the only thing the image needs.

FROM scratch
COPY my_app-aarch64-linux /my_app
ENTRYPOINT ["/my_app"]
CMD ["start"]

For every platform, from one machine

Each platform’s file starts from that platform’s runtime, ampoule-<target> from a release, kept next to ampoule. Step 1 fetches it when you pick a different machine to run on; name each target to pack.

$ ampoule release --target aarch64-darwin \
    --target x86_64-linux

Reaching the host

Start host programs

Ports, System.cmd/3 and :os.cmd/1 start the programs you list in ampoule.toml, and nothing else. Each runs on the host, and the app finds it at its usual path.

[process]
allow = ["uname", "/bin/sh"]
System.cmd("uname", ["-s"])
#=> {"Darwin\n", 0}

Bring your NIFs

C, C++ and Rust NIFs are rebuilt for wasm while it packs. The packing machine needs wasi-sdk; the machine that runs the file needs nothing.

$ ampoule release
==> building eiconv for wasm (priv/eiconv_nif.so)
==> linking the engine with 1 NIF(s): eiconv_nif
