# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static HTML/CSS with a little JavaScript, no build step and no dependencies, in `site/`, deployed by a
GitHub Actions Pages workflow (actions pinned to node24 releases).

## Users

Elixir developers shipping apps: people with a Phoenix, Francis, Ecto or plain OTP project who want
to hand a server or tool to someone as one file, without asking them to install Erlang or Elixir,
and without building a container around a runtime.

## Product Purpose

ampoule turns a Mix project into one executable file per platform. The file carries the release,
the BEAM compiled to WebAssembly and precompiled to native code, and an operating-system layer
written in Rust. Success: a developer runs `ampoule release` on their own project and ships the
resulting file.

## Positioning

The release runs unchanged, as a normal release would (`start`, `eval`, custom commands, environment
configuration, `init:stop()` on SIGTERM), inside a sandbox that only sees its own mounts. NIFs (C,
C++, Rust) are rebuilt for wasm at pack time, and one machine packs for every platform.

## Operating Context

The developer works in a terminal inside their Mix project, then copies the binary to a server, puts
it alone in a `FROM scratch` container, or hands it to someone else. Packing needs Elixir and OTP 28;
running needs nothing.

## Capabilities and Constraints

- Targets: aarch64-darwin, x86_64-darwin, aarch64-linux, x86_64-linux.
- OTP major fixed by the engine (OTP 28, ERTS 16).
- Host programs (ports, `System.cmd`, `:os.cmd`) only when listed in `[process] allow`; programs
  shipped in `priv/` are not packed. Unix domain sockets, `File.chmod`, the host pid, a memory alarm
  and restart-on-failure since v0.1.4.
- Distribution with or without epmd (one node per address without the host's epmd); NIF threads must return rather than call `enif_thread_exit`.
- Released: v0.1.7 on GitHub Releases, one binary and one archive (with the NIF kit) per target.

## Brand Commitments

- Name: ampoule, lowercase. An ampoule is a sealed glass vial holding a single dose; in French the
  word also means light bulb.
- Logo: `assets/logo.svg` (and `assets/logo-small.svg` for 16px), generated by `scripts/logo.exs`:
  the four bytes every WebAssembly module starts with, `00 61 73 6D`, as a 2×2 grid of tiles with
  seven-segment hex digits, in WebAssembly blue `#654ff0`, Elixir purple `#4e2a8e` and ink `#17181a`.
- Colours: WebAssembly blue `#654ff0` and Elixir purple `#4e2a8e`, so the site reads as Elixir plus
  wasm at a glance (user decision; it replaces an earlier no-purple rule).
- Tone: never set ampoule against other tools (no crossed-out lists of what you no longer need);
  show what it does.
- License: Apache-2.0.
- Voice: plain and concrete; show commands and real output instead of adjectives (README.md).

## Evidence on Hand

- Measured on `examples/francis` (aarch64-darwin): packs to 13.4 MiB (v0.1.7; 26.3 MiB before the
  lean runtime) in 0.3 s after `mix release`; first HTTP response about 0.3 s after launch (about 1
  s on a cold first run).
- Real terminal output from `ampoule release` (README.md).
- The Linux binary, cross-packed from macOS, ran alone in a `FROM scratch` container; `docker stop`
  shut it down cleanly in about 1 s.
- Supabase Realtime, a large production Phoenix app, passed its own end-to-end suite (53/53) when
  packed (`scripts/realtime.exs`, run before the rename).
- Seven examples with end-to-end suites: `c_nif`, `cluster`, `francis`, `phoenix_ecto`, `ports`,
  `rustler`, `sqlite`; 48 tests in all (3, 7, 18, 6, 5, 7, 2), all passing in CI on macOS and Linux
  on 2026-10-21 (`phoenix_ecto` on Linux only).
- Measured on an Apple M5 Pro (6 performance + 12 efficiency cores, 48 GB, macOS 26.7), 2026-10-20:
  - One CPU-bound job (36 tasks × 50M integer steps) against 1 scheduler: 1.98× at 2, 3.45× at 4,
    4.9× at 6, 6.3× at 8, 8.37× at 12, 10.7× at 18 (11.2× in a second run).
  - Against native Erlang with the JIT: 1.1–1.2× slower on integer arithmetic, 2.3× slower building
    and sorting lists, 6× slower folding a 5M-element list (139 vs 23 ms).
  - examples/francis, v0.1.4, packed against the native release: launch to first HTTP 200 285 ms
    vs 380 ms (median of 5, warm; native includes its bash start script); `ab` keep-alive with 50
    connections 45–58k vs 80–87k requests/s; RSS after that load 137–141 MB vs 170–176 MB.
  - Idle RSS of a small app: 69 MB with 1 scheduler, 94 MB with 18. Smallest `--memory-max` that
    boots: 80 MiB (1 scheduler), 128 MiB (18).
  - `System.cmd/3` of a host program: 19 ms; 20 at once: 57 ms.
  - `--restart on-failure` after running out of memory: first restart after 1 s, then 2, 4, 8, 16 s.
- Absent, and not to be implied: users, testimonials, company logos, download counts, benchmarks
  against other tools (the native-Erlang comparison is ampoule's own overhead, not another tool).

## Product Principles

1. Show the mechanism, not adjectives: commands, output and numbers that were measured.
2. The app stays a normal release; ampoule changes how it ships, not how it is written.
3. Honest limits: what does not work is stated next to what does.
4. One file is the unit of everything: install, run, deploy, cross-compile.
